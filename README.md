总体思路
三条线各做一个用业界主流技术栈的项目，再用一个整合演示串起来；认可度主要靠被合并的开源 PR 和有实测数据的项目，不依赖研究方向。
背景：CS 硕士，有 C 基础、在学 Python，约半年后求职。研究方向不作为求职主线，面试被问到时能讲清即可。

为什么这样选：LangGraph 是目前生产环境最常用的 agent 框架之一，MCP 已成为 agent 接入外部工具的通用协议；RK3588 加开源大模型是国内边缘 AI 的常见方案；开源 RTOS 的贡献记录可以公开验证，比个人练习项目更有说服力。
项目组合
三个项目各自独立，任何一个单独拿出来都能支撑一类岗位的简历。
Agent 项目建议选一个真实场景，比如技术文档研究助手或代码仓库问答助手；整合演示是加分项，时间不够可以跳过。
按周学习计划
顺序是底座、嵌入式、agent、端侧部署、整合与开源、求职；每月末的里程碑完成即打勾，拖了就按文末的取舍原则砍。

每个方向都会问的
• 项目细节：设计取舍、踩过的坑、怎么验证效果。面试官常追问到答不上为止，提前准备。
• 基础课：操作系统、计算机网络、数据结构与算法。
• 研究经历：简单讲清做了什么、用了什么方法即可，不必展开。
简历写法
• 用数字说话：如评测准确率、每秒 token 数、首字延迟、内存占用。
• 写清开源贡献：项目名、PR 链接、改了什么、是否已合并。
进度落后时的取舍
三条线里最终选一条做深，其余做到能讲清即可；开源贡献比竞赛更适合半年的时间窗口。
1. 先定主线：第 3 个月末，根据哪条线做得最顺、最喜欢，选一条作为主线，后面多给它时间。
2. 整合演示可砍：第 17 周的整合演示是加分项，时间不够就跳过。
3. 嵌入式 Linux 驱动可简化：只做最基础的字符设备驱动，能讲清原理即可。
4. 不能砍：每条线的里程碑项目、至少一次开源贡献尝试、第 6 个月的面试准备。
